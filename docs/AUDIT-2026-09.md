## High

**H1 — an attestation with no expiry and no binding.** The attestation
carries no `expires_at`, no nonce and no audience. The README's
verification snippet checks only the signer, so a consumer following it
accepts an attestation from months ago, about a different address than
the one it is transacting with, or one generated with `?offline=1` over
an old capture. Where: `src/attest.ts`, `README.md`. Fix: `expires_at`
inside the signed body; a README section "What this attestation does NOT
prove" (freshness beyond `expires_at`, the address binding being the
consumer's job, the capture age carried in `evidence.fetched_at`).
Status: **open, frozen.**

## Decisions taken by the owner, 2026-09-06 (frozen)

- **Topic:** `?offline=1` on the live server. **Decision:** move
  `source` (`live`, `cache` or `fixture`) **inside the signed body**.
  **Reasoning:** today the label is in the `X-KYA-Source` header,
  outside the signature, so a consumer who forwards the attestation
  forwards it without the label. A three-value enum, zero cost, aligned
  with the repository's own principle that nothing stale is served
  unlabelled.

## Answer to the briefing's item 1 (does not change code)

The briefing for the jury's finding asks first: **which file does Railway run
in production?** `package.json` has `"start": "tsx src/server.ts"`, and there
is no `railway.json`, `Procfile` or `Dockerfile` overriding it. So production
serves `GET /verify` behind the daily budget; `demo/paid-endpoint.ts` is not
exposed. In the briefing's own words: design debt, not a fire. The fix stands;
the urgency does not.

### Re-audit, snapshot 2026-09-10, commit `36b1ee7`

Commands, exactly as run, against the tree whose lockfile this PR does
not touch:

```fish
npm audit --omit=dev
npm audit --audit-level=moderate
npm audit fix --dry-run
npm ls axios ws
```

`npm audit --omit=dev`: **32 vulnerability entries (2 high, 30 moderate,
0 critical, 0 low)**. npm's unit is one entry per affected package
reachable in the tree. The 32 entries fold 19 underlying advisories over
6 vulnerable packages (axios 10, ws 2, hono 3, qs 2,
decode-uri-component 1, uuid 1); the other 26 entries are packages
flagged only because they depend on a vulnerable one.
`npm audit --audit-level=moderate` (full tree, dev dependencies included)
returns the same 32: the dev tree (`@types/*`, `typescript`) contributes
nothing, so every finding sits on a runtime dependency.

The 2 high are **axios** and **ws**. Both are transitive: neither is a
direct dependency of this repository and nothing in `src/` imports
either.

- **axios**, range 1.0.0 - 1.17.0, pinned 1.16.0 in the tree. Ten
  advisories: nine moderate and one high (`GHSA-gcfj-64vw-6mp9`, "Node
  HTTP adapter can use an inherited proxy after interceptor config
  cloning"). Reach: `x402-express` (direct, runtime) →
  `@coinbase/cdp-sdk` → axios, also via `axios-retry`.
- **ws**, range 8.0.0 - 8.20.1, pinned 8.18.0 in the four copies under
  `@walletconnect/utils` → `viem@2.23.2`. Two advisories: one moderate
  (`GHSA-58qx-3vcg-4xpx`, uninitialized memory disclosure) and one high
  (`GHSA-96hv-2xvq-fx4p`, memory exhaustion DoS from tiny fragments).
  Reach: `x402-express` → `x402` → wagmi → `@wagmi/connectors` →
  `@walletconnect/*` → `viem@2.23.2` → ws. Two neighbouring installs are
  clean: the direct runtime dependency `viem@2.55.16` pulls `ws@8.21.0`,
  outside the vulnerable range, and the `ws@7.5.13` under
  `@walletconnect/jsonrpc-ws-connection` sits below it.

The 30 moderates ride the `x402` → wagmi → `@walletconnect` chain (plus
`qs`, `hono` and `uuid` inside the same chain) and leave only through a
breaking downgrade of `x402-express` to 0.4.1, which stays undone;
Dependabot (item 12 of `DECISIONS.md`) handles them upstream.

`npm audit fix --dry-run` plans changes to `body-parser` (1.20.6 →
1.20.8, plus a nested `qs`), `hono` (4.13.2 → 4.13.7) and
`@metamask/utils` (11.11.0 → 11.12.1) — and nothing else. To close the
question, the non-breaking fix was applied to a throwaway copy of the
tree (the repository lockfile untouched): the copy went 32 → 30 (2 high
remain) and `axios@1.16.0` / `ws@8.18.0` came out exactly where they
were. The earlier claim recorded here — that the fix was "a plain,
non-breaking `npm audit fix`" — was not reproduced and is withdrawn.
Updating axios is its own work: a separate PR, validated with the
lockfile, the offline suite and the typecheck. `ws` leaves only with the
breaking `x402-express` 0.4.1 downgrade, which stays undone. **This
documentation PR changes no `package.json` / `package-lock.json` and does
not declare the highs resolved.**

Advisory-database drift, recorded instead of hidden: the 2026-09-05 pass
predates most of these advisories, which is why it recorded zero for the

## What holds up

- Secret hygiene is clean in the tree and the history.
- `verify.ts` is the single orchestrator; the gate and the server share one
  pipeline, verified by import graph.
- The gate fails closed, before settlement, and says so in the response body.
- Thresholds are measured and reproducible (`scripts/calibrate.ts`); weights are
  chosen and labelled as chosen. The file that holds them says which is which.
- `DECISIONS.md` records corrections to the project's own earlier claims
  (D18/D19), which is rarer than it should be.
